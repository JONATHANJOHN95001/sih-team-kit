Team INNOV8 · SIH26042

Team INNOV8 is building the Vernacular Pedagogy and Real-Time Translation Tool for Government of Jharkhand: a teacher records or types a lesson in Hindi, and a child reads and hears it in their mother tongue. Here is everything the project itself needs on top of the setup above.

Total new installs: one npm package and one font. Everything else is already on your machine after the six steps above. That is why we chose this statement.

1 · Bhashini API key free · required

The Government of India's own language platform does all the translation, speech recognition and speech synthesis. We are not building AI. We are building the teaching tool on top of theirs.

Sign up, verify your email, then go to My Profile and generate a key. You need three values: userID, ulcaApiKey and an Inference API key.

Get a Bhashini key

2 · Noto Sans Ol Chiki easy to miss

Santali is written in the Ol Chiki script, and Windows does not ship a font for it. Without this, every translated word renders as an empty box and the demo dies in front of the judges.

It is free from Google Fonts. Add one line to index.html and set it as the font for any Santali text.

<link rel="stylesheet" href="https://fonts.googleapis.com/css2?family=Noto+Sans+Ol+Chiki&display=swap">

3 · idb offline cache

A small wrapper around IndexedDB for caching lessons and audio so the app works with no connection. localStorage can hold the text, but audio files need IndexedDB.

npm install idb

4 · The same model, offline removes our biggest risk

IndicTrans2 is the translation model Bhashini actually serves, and AI4Bharat publish the weights openly. That means we can run it ourselves with no key, no network and no rate limit, and if Bhashini is down or the venue wifi dies during judging, the demo keeps working.

Take the distilled indic-indic-dist-320M rather than the 1B version. On a 4 GB graphics card the small one leaves room for Chrome and the dev server; the large one does not, and judging is exactly when everything is open at once. Santali is sat_Olck.

NLLB-200 from Meta also covers Santali and makes a useful second opinion when a translation looks wrong. CTranslate2 shrinks either model to int8 and runs it several times faster on the processor alone.

Hugging Face → AI4Bharat is where the weights live. You also need IndicTransToolkit for preprocessing, because skipping it produces nonsense rather than an error.
Install with pip install torch transformers ctranslate2 sentencepiece. This is a separate Python process, not something LM Studio can load.

5 · Speech, in both directions all three confirmed

This was the open question for weeks, and the answer is better than we assumed. Checked against the government's public model catalogue, Bhashini carries all three pieces:

Santali speech output. Bhashini IITM TTS for Santali, FastPitch with a HiFi-GAN vocoder, in male and female voices. This is the one that matters: Santali literacy is low, so a child who cannot yet read Ol Chiki can still hear the lesson.
Santali speech input exists too, in AI4Bharat ASR (conformer) Santhali. We had not counted on this. It means a child can also speak and be understood, which opens up a two-way conversation rather than a one-way translation.
Hindi speech input has five models to choose from, so the teacher speaks instead of typing. faster-whisper stays as the offline fallback, and Vosk at around 50 MB if a laptop struggles.

Because both directions work, the demo can be a genuine spoken exchange: the teacher speaks Hindi, the child hears Santali, the child answers in Santali, the teacher hears Hindi. That is a much stronger thing to put in front of judges than a text box.

6 · Working with no signal the winning answer

Every judge will ask how this works in a village with no connectivity. The strongest possible answer is to turn the wifi off in front of them and keep using the app.

Transformers.js runs a quantised model inside the browser tab itself, so translation happens on the device with nothing sent anywhere. Workbox generates the service worker that keeps the app and the model cached after the first visit, and Dexie stores the phrase history and glossary in the browser's own database.

Pre-load everything before you present. The first visit downloads a few hundred megabytes, and that is not something to do live on venue wifi.

7 · Proving it actually works

Translation into Santali will be mediocre, because it is a genuinely low-resource language. Every team hides this. We should measure it instead.

FLORES-200 includes professionally translated Santali sentences. Running our output against it gives a real score, and showing judges a measured number instead of a confident claim is the kind of rigour that separates the top three from everyone else.

Then add a correction box: when a user fixes a bad translation, save it to our glossary and reuse it. That turns the weakness into the feature, and it is about an hour of work.

8 · Where the Python model actually runs easy to get wrong

This is the one piece of the architecture that catches people out. Neither Vercel nor Cloudflare Pages can run IndicTrans2. They host static files and small JavaScript functions; our translation model is PyTorch and needs a real Python process with a couple of gigabytes of memory. Deploying the React app there is correct. Expecting it to carry the model is not.

So the model lives in one of three places, and we should decide which before we start:

On the presenting laptop. Simplest and fastest, no hosting at all, and it makes the offline story honest. This is the default and probably the right answer.
Render if we want it reachable from any phone. Its free tier runs an actual Python service, which is exactly what Vercel cannot do. It sleeps when idle and takes about a minute to wake, so open it before judging starts.
Hugging Face Inference as the no-setup option, at the cost of depending on someone else's uptime during our demo.
Streamlit is worth knowing for hour two. It turns a Python script into a working web page, so we can have a real translate box on screen in about fifteen lines, long before the React app exists. Prove the model works, then build the proper interface around it.

The demo, minute by minute rehearse this

Now that speech works in both directions, the demo stops being a translation box and becomes a conversation. That changes what we show and the order we show it in. Five minutes, rehearsed until nobody has to think.

0:00The problem, in one sentenceA child in a Jharkhand classroom speaks Santali at home and is taught in Hindi. Do not explain the technology yet. Judges have heard forty pitches; open with the child, not the architecture.
0:30Teacher speaksSay a real sentence in Hindi into the microphone. Nobody types anything. The Hindi appears as text while you are still speaking.
0:50Child reads and hearsSantali appears in Ol Chiki, and then plays aloud. Let the audio finish before you speak over it, because the silence is doing the work.
1:20The moment she answers backSpeak Santali into the app and let the teacher hear it in Hindi. This is the whole demo. Most teams show translation going one way; a two-way spoken exchange is a different category of thing, and it is worth pausing for a beat so the room registers what just happened.
2:00Turn the wifi offSwitch off connectivity in front of them, then do the exchange again. Every judge is going to ask how this works where these children live. Answer it before they ask, by doing it.
2:40Fix a wrong wordCorrect a bad translation in the app, then use the phrase again and show the correction stuck. Santali is low-resource and the output will be imperfect, and owning that beats hoping nobody notices.
3:10Show the numberOur FLORES-200 score. One measured figure, honestly stated, lands harder than any adjective.
3:40How it is builtNow the architecture slide: Bhashini for the models, the same models locally for offline, Supabase for the glossary. Thirty seconds. They have already seen it work.
4:20Who it reachesRoughly 7.6 million Santali speakers, and the same pipeline covers the other scheduled languages without new code. Say the number, name the source.
4:45Stop talkingEnd early and leave time for questions. Running to the buzzer reads as poor preparation.
Before you walk up: microphone permission already granted, Supabase awake, the local model already loaded once so the first translation is not the slow one, phone hotspot ready, and the OBS recording open in a background tab. If anything fails live, switch to the recording and keep narrating. Do not debug in front of judges.
